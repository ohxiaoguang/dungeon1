# 城镇升级触控审计与验收

适用：Darkest Dungeon 1.3.0，title `01008F1008DA6000`，main Build ID
`ff2bf22565188d11ea0981ee0e2b53ce`，SDK Build ID `b33804825108340e4cad9d080a636a3f`。
下面地址均为模块内偏移。

## 当前结果（2026-11-03）

用户已确认本轮设备测试通过，包括公会技能初次解锁与后续升级、铁匠铺武器/护甲、
扎营训练师与建筑升级树。触控板手势和模式切换重置也已由用户验收。

直接触控且开启触控策略时，受支持的条目轻点查看名称、说明与条件；按住至少 0.5 秒后
松手执行一次游戏原生购买。移动超出阈值、第二根手指或系统取消不购买；同一触点只允许
购买一次，初次解锁与后续升级共用该额度。价格、等级、资源与其他条件仍由游戏检查。
关闭策略后恢复原行为。Mac 鼠标与虚拟触控板不使用这套升级过滤规则。

## 实际购买入口

| 路径 | 入口 | Callable vtable | 关键数据 |
|---|---|---|---|
| 初次解锁 | `0xc97fc0` | `0x1181ba8` | `capture+8` 为树；`capture+0x10` 为 PurchaseIdentifier |
| 后续等级升级 | `0xc98330` | `0x1181b18` | `capture+8` 为树；树 `+0x90/+0x94` 为条目标识 |

两只 callable 都属于 UpgradeTreeDisplay。入口过滤发生在原函数体执行前，允许后继续
原有代码，不替代购买函数、不改写存档、不绕过资源或等级判断。`FILTER_DD_UNLOCK=6`、
`FILTER_DD_UPGRADE=5`；返回不允许时直接退出该入口。

## 设施识别与长按时序

| 设施 | 说明 callable / vtable | 观测 |
|---|---|---|
| 公会 | `0xc16d20` / `0x1177c40` | OBS 31 |
| 铁匠铺武器和护甲 | `0xbf3010` / `0x1174858` | OBS 32 |
| 扎营训练师 | `0xbff6d0` / `0x1175b28` | OBS 33 |
| 建筑升级树 | `0xbfaf70` / `0x1175018` | OBS 34 |

共同工厂为 `0xc95f30`：调用者 `0xbf1d48`、`0xbf6824`、`0xbfe4b4`、`0xc15cdc`
分别装配铁匠、建筑、扎营、公会的升级树。树 vtable 为 `0x1181770`。
`0xc96114/0xc9611c` 把说明函数对复制到树 `+0x130`；`0xbf2480` 的复制逻辑确认
两个 std::function 的 callable 指针位于树 `+0x150/+0x180`。据此识别绑定类型，
无需等待锁定条目先运行说明回调。原公会等级升级的条目标识识别保留作兼容后备。

行观测将当前单触点保持在 Host 的 hold-tap 模式：约 0.5 秒后仍可在松手时产生游戏
需要的 Tap，而不是 Press→Complete。购买前过滤器检查接触时长、取消状态及一次性额度。
设施观测各自检查门控、相邻指令与 vtable；共有入口另校验构造/复制布局及 main/SDK
Build ID。只覆盖上述类型的升级树，不宣称所有外观相似按钮都受支持。

## 调查中纠正的判断

1. `0xc16320` 是购买后的公会通知，不是购买前入口。早期 Mac 点击断点命中并伴随扣费
   只能证明关联。设备日志出现短按 BLOCK 但仍升级后，过滤器移至真正的购买前入口；
   原通知现在完整保留。
2. 初次解锁绕过后续等级点击入口，必须分别处理。
3. 只用“已经运行过说明回调”的 kind/id 名单会漏掉锁定条目。设备日志的 unlock
   `guild=0` 暴露此问题；最终用树绑定类型识别。回归检查明确覆盖未显示过说明的条目。
4. 取消后触点数归零不能当作无触点来源直接放行，必须保留 CANCELLED 判定。
